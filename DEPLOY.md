# Развёртывание: сервер в Docker на VPS + клиент на Windows 10

Схема: **клиент (Windows)** поднимает локальный SOCKS5 и туннелирует через
**сервер (VPS, Docker)** по TLS с браузерным отпечатком. Наружу это выглядит как
обычный HTTPS.

---

## 1. Сервер на VPS (Docker)

Нужен Docker + docker compose. Скопируйте весь проект на VPS (git clone или
`scp`), затем из корня проекта:

```bash
docker compose up -d --build
docker compose logs        # <-- здесь напечатан публичный ключ сервера
```

В логах найдите строку:

```
СТАТИЧЕСКИЙ ПУБЛИЧНЫЙ КЛЮЧ СЕРВЕРА (передайте клиенту):
  e518bd65a51a15db......844e1547
```

**Скопируйте этот 64-символьный hex - он нужен клиенту.** Ключ хранится в томе
`chameleon-data`, поэтому при перезапуске контейнера он не меняется.

Порт: compose пробрасывает `443 -> 8443`. Клиент подключается к `IP_VPS:443`.
Откройте 443/tcp в фаерволе/облачной security-group.

### Опции (в `docker-compose.yml`, секция `environment`)

- `CHAMELEON_SNI` - домен, под который маскируется TLS (SNI и CN самоподписанного
  сертификата). По умолчанию `www.example-cdn.com`.
- `CHAMELEON_DECOY=example.com:443` - включает декой-прокси: чужак/зонд без ключа
  увидит контент этого реального сайта, а не заглушку. Рекомендуется.
- `CHAMELEON_CERT_PFX` / `CHAMELEON_CERT_PASS` - боевой сертификат (.pfx) вместо
  самоподписанного. Для максимальной незаметности используйте реальный домен и
  реальный сертификат (Let's Encrypt -> сконвертируйте в .pfx, положите в том
  `chameleon-data`, укажите `CHAMELEON_CERT_PFX=/data/cert.pfx`).

Остановить / обновить:
```bash
docker compose down
docker compose up -d --build
```

## 2. Клиент на Windows 10

Нужен .NET 9 SDK (или Runtime для готового бинарника).

### Вариант А: запуск из исходников
```powershell
dotnet run --project src/Chameleon.Client -- IP_VPS:443 <PUBKEY_HEX>
```

### Вариант Б: собрать один .exe
```powershell
dotnet publish src/Chameleon.Client -c Release -r win-x64 --self-contained ^
  -p:PublishSingleFile=true -o publish
publish\Chameleon.Client.exe IP_VPS:443 <PUBKEY_HEX>
```

Аргументы:
```
Chameleon.Client <server_host:port> <server_pubkey_hex> [socks] [sni]
```
- `socks` - локальный адрес SOCKS5, по умолчанию `127.0.0.1:1080`.
- `sni` - должен совпадать с `CHAMELEON_SNI` сервера (по умолчанию совпадает).

Клиент напечатает:
```
SOCKS5-прокси слушает на 127.0.0.1:1080
```

> ChaCha20-Poly1305 на Windows 10 отсутствует в системе - клиент автоматически
> использует встроенную реализацию, никаких действий не требуется.

### Мультипуть (необязательно)
Дополнительные несущие (другой IP/CDN/ретранслятор) - через запятую:
```powershell
$env:CHAMELEON_EXTRA="IP2:443,IP3:443"
dotnet run --project src/Chameleon.Client -- IP_VPS:443 <PUBKEY_HEX>
```

## 3. Направить трафик в туннель

Укажите приложению/системе SOCKS5-прокси `127.0.0.1:1080`.

- **Firefox:** Настройки -> Сеть -> Ручная настройка прокси -> SOCKS v5 хост
  `127.0.0.1`, порт `1080`, «Проксировать DNS при SOCKS v5».
- **Chrome/Windows:** запустите с `--proxy-server="socks5://127.0.0.1:1080"`
  или задайте системный прокси.
- **Проверка из консоли:**
  ```powershell
  curl --socks5-hostname 127.0.0.1:1080 https://ifconfig.me
  ```
  Должен вернуть IP вашего VPS.

---

## 4. Проверка, что всё живо

На сервере: `docker compose logs -f`. На клиенте - строка про SOCKS5 и
`несущих в сессии: 1`. Если запрос через `curl --socks5-hostname` доходит -
туннель работает.

## Важные оговорки

- Это **исследовательский прототип**. Самоподписанный сертификат + приём любого
  серта на клиенте годятся для проверки работоспособности, но для реальной
  скрытности нужен настоящий домен, настоящий сертификат и, в идеале, пиннинг.
- **Прохождение ТСПУ не гарантировано** и проверяется только на месте, у вашего
  оператора, и заново после каждого обновления систем фильтрации.
- Сервер сейчас принимает любого клиента, прошедшего рукопожатие с его публичным
  ключом (нет allowlist клиентских ключей). Для приватного сервера этого обычно
  достаточно, но помните об этом.
- Криптография местами не константного времени (см. README) - не для
  высокорисковых сценариев без замены на аудированную библиотеку.
