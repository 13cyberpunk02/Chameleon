# Chameleon

**Экспериментальный протокол обхода блокировок на C#/.NET.** Не ещё одна обёртка
над TLS, а попытка спроектировать транспорт, устойчивый сразу по всем осям, по
которым современные системы фильтрации (в т.ч. российский ТСПУ) отличают туннель
от обычного трафика.

>  !!!️ **Это исследовательский прототип, а не готовый к бою продукт.** Он создан,
> чтобы проверить набор идей и понять, что реально достижимо на .NET. Гарантий
> обхода конкретной цензуры нет и быть не может - см. раздел «Ограничения».

---

## Зачем это

Существующие протоколы (VLESS Reality, VLESS XHTTP, AnyTLS, Hysteria2) хорошо
маскируют *содержимое*, но у каждого есть слабое место:

- **Отпечаток TLS.** ClientHello от библиотеки часто не совпадает с браузером по
  JA3/JA4, и это ловится пассивно, на самом дешёвом слое фильтрации.
- **Поведение потока.** Ровный проксирующий поток без пауз и с нетипичными
  размерами пакетов виден статистически, даже когда байты зашифрованы. На этом
  всё чаще спотыкается Reality.
- **Активное зондирование.** Цензор сам подключается к серверу и смотрит, ведёт
  ли он себя как заявленный сайт.
- **Хрупкость одного пути.** Один сервер, один IP, одно долгоживущее соединение -
  убили несущую или включили whitelist, и сессия умерла.

Chameleon целится не в одну из этих проблем, а во все сразу.

## Идея

Протокол разделён на независимые слои, а маскировка - это в первую очередь
*поведение и отпечаток*, а не заголовки:

1. **Сессия, не привязанная к соединению.** Логическая сессия живёт поверх одной
   или нескольких «несущих». Данные режутся на пакеты с номерами; потеря или
   троттлинг одной несущей не рвёт сессию.
2. **Программируемый шейпинг трафика.** Конечный автомат модели поведения решает,
   когда и какого размера слать пакеты и когда добавлять фиктивный трафик.
   Модели можно обучать на реальном трафике и менять на лету.
3. **Отпечаток под настоящий браузер.** TLS-несущая формирует ClientHello,
   совпадающий по JA4 с реальным Chromium (Chrome/Brave/Edge…).
4. **Прикрытие под сайт-декой.** Активный зонд без ключа видит живой настоящий
   сайт (обратный прокси), а не заглушку.
5. **Адаптивный транспорт.** Различение искусственного троттлинга (полисинга) и
   настоящей перегрузки; мультипуть; FEC для восстановления потерь без ожидания
   ретрансмита.


## Архитектура

```
┌──────────────────────────────────────────────────────────────┐
│ Приложение (SOCKS5) → потоки пользователя                    │
├──────────────────────────────────────────────────────────────┤
│ СЕССИЯ: мультиплекс потоков, номера пакетов, ACK/ретрансмиты,│
│          пересборка по offset, мультипуть                    │
├──────────────────────────────────────────────────────────────┤
│ ШЕЙПЕР: конечный автомат поведения (размеры + тайминги)      │
├──────────────────────────────────────────────────────────────┤
│ RECORD-СЛОЙ: ChaCha20-Poly1305 + маскированная длина         │
├───────────────┬───────────────┬──────────────────────────────┤
│ Несущая #1    │  Несущая #2   │  Несущая #N                  │
│ TLS (JA4)     │  TLS / relay  │  …                           │
└───────────────┴───────────────┴──────────────────────────────┘
      ▲ рукопожатие Noise IK (X25519) на первой несущей,
        присоединение остальных по HMAC от session_secret
```

## Состав солюшена

| Проект | Назначение |
|--------|------------|
| **Chameleon.Core** | Ядро без внешних зависимостей: криптография, протокол, сессия, прокси, транспорт, детектор полисинга, FEC. |
| **Chameleon.Tls** | TLS-несущая с ClientHello под профиль Chromium (JA4), утилиты `Ja3`/`Ja4`. Зависит от NuGet `BouncyCastle.Cryptography`. |
| **Chameleon.Playground** | Демонстрации и проверки (каждая ревизия - свой запускаемый пример). |

Ключевые директории `Chameleon.Core`:
`Crypto` (Noise IK, X25519, ChaCha20-Poly1305, вывод ключей) ·
`Protocol` (varint, фреймы, кодек пакетов) ·
`Transport` (record-слой, рукопожатие, присоединение несущих, TLS) ·
`Session` (мультиплекс, надёжность, мультипуть, шейпер) ·
`Proxy` (SOCKS5, клиент, сервер, relay, декой) ·
`Congestion` (детектор полисинга) ·
`Fec` (Reed-Solomon).

## Сборка и запуск

Требуется .NET SDK начиная с 9 и выше.

```bash
dotnet build
dotnet run --project src/Chameleon.Playground   # демонстрация текущей ревизии
```

Схема боевого использования (клиент локально, сервер на VPS):

```csharp
// Сервер знает свой приватный статический ключ; клиент - публичный.
var server = ChameleonServer.Start(
    endPoint, serverStatic,
    carrier: TlsCarrier.Server(certificate),
    decoy:   new DnsEndPoint("real-site.example", 443)); // сайт-прикрытие

var client = await ChameleonClient.StartAsync(
    serverEndPoint, clientStatic, serverStaticPublic, socksEndPoint,
    carrier: BcTlsCarrier.Client("www.example-cdn.com"),  // ClientHello под Chromium (JA4)
    shaper:  TrafficShaper.WebBrowsing,                    // модель поведения
    extraCarrierEndpoints: new[] { secondEndpoint });      // мультипуть / ретранслятор
```

Дальше любой SOCKS5-совместимый софт направляется на локальный порт клиента.

## Примеры
 
В `Chameleon.Playground` — по одному файлу на возможность (папка `Examples/`),
запуск через диспетчер:
 
```bash
dotnet run --project src/Chameleon.Playground -- <имя>
dotnet run --project src/Chameleon.Playground -- all   # все по очереди
```
 
| Имя | Что показывает |
|-----|----------------|
| `handshake` | Рукопожатие Noise IK + record-слой + отпор активному зонду |
| `socks5`    | Сквозной SOCKS5-прокси поверх голого TCP |
| `tls`       | Прокси поверх TLS + декой-прокси (зонд видит настоящий сайт) |
| `ja4`       | Отпечаток ClientHello: JA3/JA4 против эталона Chromium/Brave |
| `shaper`    | Стохастический шейпер-автомат + смена модели на лету |
| `models`    | Обучение модели поведения из сэмплов, JSON, загрузка |
| `policing`  | Детектор полисинга vs перегрузки |
| `multipath` | Две несущие, убийство одной посреди передачи 400 КБ |
| `join`      | Присоединение несущих по сети: три несущие в одной сессии |
| `fec`       | Reed-Solomon: восстановление потерь без ретрансмита |

## Ограничения (честно)

- **Это прототип.** Врезка FEC и адаптивного congestion-control в живой цикл ещё
  не сделана - готовы проверенные кодек и детектор, но не их интеграция.
- **Криптография не константного времени.** Собственные `X25519` и `Poly1305`
  корректны (сверены с RFC-векторами), но для боя их нужно заменить на
  аудированную библиотеку (NSec/BouncyCastle).
- **JA4, но не JA3.** Под Chromium совпадает JA4 (современный отпечаток). Точный
  JA3 на стоковом BouncyCastle недостижим (порядок расширений, GREASE).
- **Отпечаток версионно-зависим.** Профиль JA4 привязан к версии браузера; при
  обновлении его нужно пересобрать (инструкция - в README проекта BouncyCastle).
- **Главное: прохождение реальной цензуры не гарантировано.** Это проверяется
  только тестами из реальных сетей у разных операторов и после каждого обновления
  систем фильтрации - заново. Никакой протокол не может обещать обратное.
